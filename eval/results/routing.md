# Маршрутизация по документу и деление вопроса на части (LegalBench-RAG)

Замер без стенда, на замороженных векторах: нарезка naive500_title, bge-m3, точный поиск полным перебором в чистом Python (`eval/routing_eval.py`). Векторы кусков те же; новые векторы только у коротких текстов: названия документов («Document: <название>») и две части вопроса. Деление детерминированное, по первой «;»: ссылка на документ («Consider the Supply Agreement between A and B») и сам вопрос («What is the expiration date of this contract?»). Вопросов без «;» в наборах 0. Метрика посимвольная, как у авторов бенчмарка; средний R и P по k это среднее по k = 1, 2, 4, …, 64, как в статье SAC (arXiv 2510.06999). В скобках 95 % интервал (бутстреп по вопросам), Δ к базе считается парно на тех же вопросах. У всех вариантов ровно k кусков: если в выбранных документах кусков меньше, список добивается следующими документами маршрутизатора.

## Коротко

- Лучший вариант (выбран на половине A): **деление б + соседи**, документ за документом; куски ранжирует 0.25·весь вопрос + 0.75·сам вопрос; соседи μ = 0.5. Маршрутизатор: средний вектор кусков × ссылка (балл документа это косинус их векторов). На половине B мини средний recall по k 45.7 → 61.6 (Δ +15.9 [+13.9; +18.0]), средняя precision по k 7.6 → 12.3 (Δ +4.7 [+3.9; +5.5]); recall@1 10.9 → 23.6, recall@8 45.0 → 65.5, recall@64 81.8 → 90.7.
- Полный набор (6500 вопросов, параметры с мини без нового подбора): средний recall по k 43.3 → 59.4 (Δ +16.1 [+15.2; +16.9]), precision 7.2 → 12.1 (Δ +4.9 [+4.3; +5.4]); recall@64 76.5 → 88.3. Для сравнения статья SAC на полном наборе (gte-large, краткое содержание документа от LLM у каждого куска): 41.8 и 11.0; это числа статьи, не наш замер.
- Главное дало деление вопроса: ссылка выбирает документ, а куски внутри него ранжирует сам вопрос (деление б: Δ +14.1 [+12.4; +15.9] на B; соседи поверх него ещё +1.8 [+1.0; +2.6]). Δ среднего recall по k на B у остальных: жёстко top-1 +1.9 [+1.4; +2.4]; деление а -1.2 [-2.2; -0.1]; агрегация +1.5 [+1.1; +2.0].
- Маршрутизатор ставит эталонный документ первым у 100.0 % вопросов мини B и у 96.4 % вопросов полного набора.
- Ширину маршрута мини выбрать не может: на мини маршрутизатор не ошибается. Подбор на половине A полного дал top-10 документов, λ = 2; куски ранжирует 0.25·весь вопрос + 0.75·сам вопрос; соседи μ = 0.5, маршрутизатор первый кусок × ссылка: на половине B к параметрам с мини Δ среднего recall по k +1.0 [+0.6; +1.4], precision +0.2 [+0.1; +0.3].
- Приём опирается на устройство данных: вопрос LegalBench-RAG называет документ. Для юридического поиска это честно (вопрос про конкретный договор), но это выигрыш от знания, о каком документе вопрос, а не «лучше модель».

## Как выбирались параметры

Вопросы каждого набора поделены пополам с зерном 2026: половина A для подбора, B для проверки. Маршрутизатор выбран по доле вопросов с эталонным документом на первом месте (A), параметры каждого семейства по среднему recall по k на A; всего перебрано 187 сочетаний. Соседи подобраны поверх лучшего маршрута. Лучший вариант это лучший на A среди победителей семейств. На мини маршрутизатор не ошибается, поэтому «документ за документом» (λ = ∞) и «top-1 с добивкой» дают один и тот же список.

Семейства: жёстко (куски только из top-n документов, ранжирует весь вопрос); мягко (балл куска + λ·балл документа); деление а (поиск по каждой части вопроса по всему корпусу и слияние: взвешенная сумма баллов, RRF, максимум); деление б (ссылка выбирает документы, куски ранжирует сам вопрос или смесь с баллом всего вопроса); агрегация (top-200 кусков по всему вопросу, балл документа из баллов его кусков); соседи (балл куска + μ·лучший балл соседнего куска того же документа).

Чувствительность на A (средний recall по k, лучший по остальным параметрам):

- деление б, доля всего вопроса a в балле куска: 0.25 → 59.8, 0 → 59.6, 0.5 → 56.8, 0.75 → 52.3.

- агрегация, балл документа: sum3 → 47.6, mean3 → 47.6, max → 47.5, frac → 44.5.

## Что понадобится сервису

- Деление вопроса по первой «;» на ссылку и сам вопрос. Вопрос без ссылки идёт как сейчас: весь вопрос по всему корпусу. Для живых вопросов нужен свой разбор ссылки (здесь не проверялся).
- Ещё два коротких вектора на запрос (ссылка и сам вопрос), одним запросом к Ollama вместе с вопросом.
- Коллекция документов в Qdrant: точка на документ, вектор документа это среднее векторов его кусков (считается из уже загруженных векторов, без модели), payload `file` и `title`. На полном наборе 714 точек.
- В коллекции кусков индекс payload по `file` (keyword): поиск кусков с фильтром `file` = выбранный документ.
- Смесь баллов линейна: 0.25·cos(весь вопрос, кусок) + 0.75·cos(сам вопрос, кусок) это скалярное произведение куска с вектором 0.25·v(весь вопрос) + 0.75·v(сам вопрос), поэтому в Qdrant это один поиск с этим вектором.
- На запрос два вызова Qdrant: поиск по коллекции документов по вектору ссылки и точный поиск кусков лучшего документа с фильтром по `file`; если в документе меньше k кусков, такой же поиск в следующем.
- Соседи (μ = 0.5): нужны баллы всех кусков документа, то есть поиск в документе с limit = число его кусков (без текста в payload, только `start`), сглаживание и отбор top-k в сервисе, потом текст выбранных кусков по id.
- Мягкий маршрут, подобранный на полном (top-10 документов, λ = 2): фильтр `file` по 10 документам маршрутизатора и прибавка λ·балл документа к баллу куска в сервисе.

## Оговорки и что не проверено

- Приём работает потому, что вопрос называет документ. Ошибка маршрутизатора уводит выдачу в чужой договор целиком; на вопросах без ссылки выигрыша нет.
- Деление по «;» опирается на шаблон вопросов бенчмарка. Живым вопросам нужен другой разбор (правило или модель), это не мерили.
- Половины A и B делят вопросы, а не документы: документы у половин общие. Подбирается несколько глобальных чисел (маршрутизатор, M, λ, a, μ), поэтому подгонка под документы мала, но не нулевая.
- Время в чистом Python не равно времени в Qdrant; на стенде маршрут не мерили.
- Векторы кусков не менялись (та же нарезка naive500_title). Статья SAC сравнивается по её числам, у неё другая модель (gte-large) и краткое содержание документа от LLM у каждого куска.
- Полный набор: варианты с перебором всего корпуса (база для сверки, деление а, агрегация) посчитаны на подвыборке по 200 вопросов на набор, маршруты на всех вопросах без мини A.
