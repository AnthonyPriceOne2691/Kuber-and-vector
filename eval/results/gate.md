# Гейт «этого договора в базе нет» (LegalBench-RAG, 20.11.2026)

База: мини-набор, документов в ней 72 (naive500_title, bge-m3). Балл вопроса это лучший косинус ссылки на договор (часть до первой «;») с представлением документа базы. Балл ниже порога даёт отказ «этого договора в базе нет», модель не вызывается. Замер без стенда (`eval/gate_eval.py`).

- В базе: вопросы мини, половина A 388, B 388 (половины как у `eval/routing_eval.py`).
- Вне базы: вопросы полного набора, чьих документов в мини нет; половины по документам: A 3021, B 3087 вопросов (327 разных ссылок в B). PrivacyQA вне базы нет: весь набор в мини.
- Порог подбирается на A, проценты на B с 95 % интервалом (бутстреп по вопросам). AUC это вероятность, что вопрос из базы получит балл выше вопроса вне базы.

| Представление документа | AUC на A | AUC на B |
|---|---|---|
| средний вектор кусков | 0.974 | 0.983 |
| первый кусок | 0.990 | 0.981 |
| название | 0.934 | 0.943 |
| название + первый кусок | 0.996 | 0.995 |

## Вывод

- Лучше всего различает название + первый кусок (AUC на B 0.995). При пороге с A (≤ 1 % ложных отказов на A, порог 0.5858) на B ложных отказов в базе 0.3 [0.0; 0.8] %, верных отказов вне базы 97.2 [96.6; 97.8] %.
- В сервисе (app/routing.py) порог с A округлён вниз до трёх знаков. Вверх нельзя: порог с A стоит ровно на балле одного договора базы, и округление вверх отсекало его вопросы (на стенде 20.11: 11 вопросов мини при 0,586 вместо 0,5858).
- Для сравнения: без гейта модель на вопросах вне базы отказывала в 68,9 % случаев, а в 31,1 % отвечала по чужому договору (`answer.md`, 45 вопросов).
- Оговорки. Вопросы вне базы из того же бенчмарка и того же шаблона «Consider …; …». База маленькая (мини); на большой базе порог надо проверить заново. Живые вопросы без названия договора гейт не отличит: им нужен обычный путь без маршрута.
