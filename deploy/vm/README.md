# Машины стенда

Одна схема (`machine.yaml`) на все машины, роль задаётся параметром `ROLE` при создании.

| Машина | Роль | Что на ней |
|---|---|---|
| machine-1…3 | `cluster` | серверы k3s со встроенным etcd, пиры Qdrant, сервис поиска, Falco |
| machine-4 | `observer` | вход (HAProxy, TLS), генератор нагрузки, панель |
| builder | `builder` | одноразовая: качает комплект и удаляется |

Ресурсы у всех одинаковые: 2 vCPU, 4 ГБ, диск 20 ГБ. Образ Ubuntu 24.04 закреплён по выпуску и sha256.

## Сеть

- Машины стенда в общей сети socket_vmnet `shared`, интерфейс `lima0`, `192.168.105.0/24`; Мак для них это `192.168.105.1`. Сборочная ВМ в эту сеть не входит (`networks: []`): у неё есть интернет.
- Встроенная сеть Lima (`eth0`, `192.168.5.0/24`, шлюз и DNS `192.168.5.2`) остаётся для ssh и выхода сборочной ВМ. localhost Мака на ней закрыт самим гипервизором (`networkOpts.hostLoopback: false`). Проверено 18.11 со снятым файрволом ВМ: Ollama на localhost Мака не отвечает.
- Ollama для кластера идёт через фильтр на Маке (`deploy/host/filter.sh start`): слушает только `192.168.105.1:11434` и пропускает только `POST /api/embed` с bge-m3 или snowflake-arctic-embed2 и `POST /api/chat` с qwen3:8b. У чата контекст модели фиксирован, длина ответа ограничена, `keep_alive`, инструменты и картинки запрещены, к модели один запрос за раз.

Установка socket_vmnet (один раз, с sudo; выпуск v1.2.2 проверен по sha256 и подписи GPG):

```bash
sudo tar -C / -xzvf kit/host/socket_vmnet-v1.2.2/socket_vmnet-1.2.2-arm64.tar.gz ./opt/socket_vmnet
# в ~/.lima/_config/networks.yaml оставить сети user-v2 и shared, убрать bridged и host
limactl sudoers > etc_sudoers.d_lima && less etc_sudoers.d_lima
sudo install -o root -g wheel -m 0444 etc_sudoers.d_lima /private/etc/sudoers.d/lima && rm etc_sudoers.d_lima
limactl sudoers --check
```

Права `0444` нужны самой Lima: она сверяет файл правила со своим конфигом.

## Песочница

- Папок Мака нет (`mounts: []`), ключей и агента ssh нет, прокси хоста не передаётся, containerd самой Lima выключен.
- Сеть закрывает `sandbox-boot.sh` в режиме `boot`, то есть ещё до подъёма сети, на каждом старте:
  - все роли: DHCP, соседние машины (`192.168.105.0/24`) и сети k3s;
  - `cluster`: плюс фильтр Ollama на Маке (`192.168.105.1:11434`);
  - `builder`: плюс DNS и интернет;
  - всё остальное к Маку и наружу закрыто. DNS машинам стенда не нужен (всё ходит по IP), а открытый DNS это канал утечки, поэтому он закрыт.
- Вход на сети машин (lima0) закрывает `ingress.sh` (правила собирает `ingress.py` по адресам машин, служба `stand-ingress` ставит их на каждом старте до подъёма сети):
  - машине кластера пишут только соседи по кластеру (etcd 2379 и 2380, API k3s 6443, kubelet 10250, WireGuard 51820/udp) и вход machine-4 (API 6443, node_exporter 9100, NodePort 30080, 30633, 30765);
  - входу machine-4 пишут все, но только на 443, и машины кластера на 8090 (события Falco в панель);
  - остальное отбрасывается молча и считается (`ingress.sh status`); ssh между машинами по сети машин закрыт;
  - встроенную сеть Lima (eth0) фильтр не трогает, по ней ходит только Lima с Мака, поэтому `limactl shell` работает и при ошибке в правилах. Снять со всех машин: `ingress.sh off`.
- IPv6 выключен: DNS отдаёт AAAA, а маршрута по IPv6 нет, соединения висли до таймаута.
- Службы Ubuntu, которые сами ходят в сеть (автообновления, snapd, телеметрия), замаскированы (`quiet-system.sh`).
- Остаток, проверено 18.11: root на машине снимает файрвол ВМ и тогда выходит в интернет (через встроенную сеть Lima и через NAT моста) и видит службы Мака на всех интерфейсах (AirPlay). localhost Мака остаётся закрыт гипервизором. Сцена «заражённая машина» показывает реакцию, а не «атакующий заперт».
- Скрипт песочницы Lima копирует в конфиг машины при создании: правка `sandbox-boot.sh` доходит до машины после пересоздания.

## Команды

- `./kit-build.sh` собирает комплект в `kit/vm`, `./kit-build.sh security` в `kit/vm-security`, `./kit-build.sh falco` в `kit/vm-falco`, `./kit-build.sh monitoring` в `kit/vm-monitoring` (Prometheus, node_exporter, Grafana; список утверждён владельцем 19.11): одноразовая ВМ, суммы и подписи сверяются там и ещё раз на Маке, ВМ удаляется.
- `./up.sh` поднимает все четыре машины, `./up.sh machine-1` только указанные. Повторный запуск безопасен.
- `../stand-up.sh` поднимает весь стенд с нуля одной командой, `../check.sh` проверяет его. `QUIET=1 ../stand-up.sh` для кадра: в терминале только английские заголовки шагов с секундами от старта и в конце `stand ready in N s` с короткой сводкой (узлы, пиры Qdrant, поды поиска, вход, итог проверки), подробный вывод в `runs/stand-up-<время>.log`; при ошибке шага последние строки журнала и ненулевой код выхода.
- `limactl stop --force machine-2` «выдёргивает шнур» у машины.
- `limactl shell machine-1` открывает shell на машине.
