# Проверки безопасности

Атака снаружи и аудит стенда. Каждый скрипт пишет отчёты сканеров и сводку в `runs/security/<время>/`. Вывод в терминал и сводки по-английски: они идут в кадр, ролик на английском (решение владельца 19.11). Комментарии и документация по-русски. На живом стенде ещё не прогонялись (написаны 19.11 без стенда). Модель угроз со статусами мер лежит в `docs/security/threat-model.md`.

| Скрипт | Что делает | Где работает чужой код |
|---|---|---|
| `outside.sh up`, `outside.sh down` | одноразовая машина «снаружи» из той же схемы (роль `outside`, песочница без Мака и интернета, 1 vCPU, 2 ГБ), nmap из комплекта | на ней самой |
| `scan-ports.sh` | все порты TCP четырёх машин и несколько UDP (nmap), потом стук руками в Qdrant 6333, API k3s 6443, kubelet 10250, вход без ключа и перебор ключей | машина «снаружи», после скана удаляется |
| `scan-images.sh [machine-1]` | образы работающих подов выгружаются архивами, trivy с базой из комплекта ищет известные уязвимости без сети | машина «снаружи», ключей кластера там нет |
| `kube-bench.sh [machine-1]` | k3s против профиля CIS `k3s-cis-1.9` | разово на сервере k3s от root (ему нужны файлы и флаги k3s), бинарник удаляется сразу |
| `summary.py ports|bench|images ПАПКА` | сводка в Markdown; отчёты сканеров читаются как чужие данные (XML без ENTITY, размер ограничен) | на Маке, только наш код |

Чего ждём от `scan-ports.sh`: открыт только 443 на machine-4, остальные порты всех машин молчат (пакет отброшен фильтром входящих `deploy/vm/ingress.sh`, а не отвергнут), прямой стук не получает соединения, без ключа 401, перебор с одиннадцатой попытки получает 429. Если хоть одна машина отвечает отказом (closed), фильтр на ней не стоит.

Оговорки:

- nmap видит UDP-порт открытым только по ответу. WireGuard на незнакомый пакет не отвечает, поэтому для UDP молчание ничего не доказывает, его пишем как есть.
- База trivy это снимок на дату сборки комплекта (`kit/vm-security/SOURCES.tsv`), дата стоит в сводке. Уязвимость новее снимка сканер не увидит.
- Профиль kube-bench писался под Kubernetes 1.27–1.29, у стенда 1.37. Часть FAIL и WARN может оказаться несовпадением флагов, их разбираем руками по самооценке k3s, прежде чем писать в итог.
- Машине «снаружи» нужно около 2 ГБ памяти Мака на время скана (оценка).
