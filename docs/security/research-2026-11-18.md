# Защита стенда k3s + Qdrant + поиск: практика и стандарты на 18.11.2026

Разведка по первоисточникам (документация проектов, CIS, NSA/CISA, OWASP, release notes, advisory), 18.11.2026. В квадратных скобках — номер источника из раздела 4, там же дата или версия. «Оценка» — суждение автора без источника. Документы старше 2025 г. помечены «может быть устаревшим».

## 1. Что нового в 2025–2026

1. **CIS под k3s 1.37.** Общий CIS Kubernetes Benchmark перешёл на ветку 2.x: v2.0.1 (06.2026), v2.1.0 (10.2026, добавлены Kubernetes 1.36–1.37) [1, 2]. Для k3s эталон — «CIS 2.0 Self-Assessment Guide» для k3s v1.34–v1.37 плюс hardening guide (обновлён 17.11.2026) [3, 4]. kube-bench отстаёт: v0.16.0 (05.08.2026), новейший k3s-профиль `k3s-cis-1.11` рассчитан на k3s v1.29–v1.32 [5, 6]. NSA/CISA Kubernetes Hardening Guide — по-прежнему v1.2 (08.2022), более новой редакции не нашёл; может быть устаревшим [7].
2. **Kubernetes 1.34–1.37** [8–11]. GA: в 1.34 — AuthenticationConfiguration, анонимный доступ только к заданным эндпоинтам, упорядоченное удаление namespace (против CVE-2024-7598); в 1.36 — user namespaces (`hostUsers: false`), fine-grained авторизация kubelet API, MutatingAdmissionPolicy, внешняя подпись SA-токенов; в 1.37 — Pod Certificates и ClusterTrustBundle, StorageVersionMigration (перешифровка после смены ключа). Beta: проверка прав пода на закэшированный образ (1.35, включена), admission-политики из манифестов на диске, которые нельзя удалить через API (1.37). Убрано и устарело: том `gitRepo` удалён (1.36), `Service.spec.externalIPs` объявлен устаревшим (1.36, CVE-2020-8554), kubelet по умолчанию не стартует на cgroup v1 (1.35).
3. **Qdrant: три advisory за 2026 г.** Запись произвольных файлов через `/logger`, хватало read-only-ключа (CVE-2026-25628, <1.15.6) [31]; read-only-ключ и JWT принимались внутренним API (1.18.0–1.19.1) [30]; внутренний gRPC-порт 6335 в кластере без аутентификации: чтение реплик, подмена топологии, исчерпание памяти (<1.20.0, CVSS 9.8) [29]. С 1.20.0 `enforce_internal_auth` включён по умолчанию, **но действует только при заданном `api_key`** [27, 29]. Наша v1.20.2 — последняя (16.11.2026) [32].
4. **Цепочка поставок.** Компрометация Trivy 19–23.03.2026 (GHSA-69fq-xp46-6x23): вредоносный v0.69.4 выпущен их же релизным конвейером, 76 из 77 тегов trivy-action переписаны; не пострадали образы по digest и иммутабельные релизы; advisory велит сверять подпись и её время с окном атаки и ротировать секреты атомарно [48]. GitHub сделал 3-дневную «выдержку» новых версий в Dependabot настройкой по умолчанию (23.07.2026) [51]. SLSA v1.2 (24.11.2025) добавил трек Source [50]. CISA 2025 SBOM Minimum Elements добавляет хэш компонента, лицензию, инструмент и контекст генерации (черновик 08.2025) [52].
5. **TLS.** Рекомендации Mozilla Server Side TLS переданы сообществу TLSRef: v5.8 — гибрид X25519MLKEM768 первым в списке групп, DHE убраны из Intermediate; v6.0 — убран профиль Old [34, 35]. X25519MLKEM768 стандартизован в RFC 10024 (08.2026) [36]. HAProxy умеет его только в своих сборках с AWS-LC (Community ≥3.3) [37].
6. **ИИ-инфраструктура.** Модельные серверы без аутентификации — массовая цель: Ollama CVE-2026-7482 «Bleeding Llama» (утечка памяти процесса через `/api/create` + `/api/push`, исправлено в 0.17.1) и CVE-2026-5757 (≤0.13.5) [43, 44]. OWASP Top 10 for LLM Applications — всё ещё редакция 2025 (вышла 11.2024; может быть устаревшим), для нас важен LLM08 «Vector and Embedding Weaknesses» [45]. NSA/CISA/FBI «AI Data Security» (22.05.2025) — про цепочку данных и отравление [46].
7. **Рантайм и сканеры.** Falco 0.45.2 (29.10.2026), Tetragon 1.8.0 (снижено потребление памяти), Kubescape 4.0 (03.2026, runtime-детект GA) [55, 59, 61]. С 01.06.2026 CVE-2020-8554, CVE-2020-8561, CVE-2020-8562 и CVE-2021-25740 помечены как «затрагивают все версии» — сканеры покажут их на любом кластере; ответ — компенсирующие меры, а не обновление [19].

## 3. Минимум для демо и что отложить

**Бюджет.** k3s-сервер со встроенным etcd и нагрузкой занимает около 1,6 ГБ [25]; на ВМ с 4 ГБ остаётся около 2,4 ГБ на Qdrant, поиск, Traefik и защиту (оценка). Поэтому всё встроенное (NetworkPolicy k3s, ValidatingAdmissionPolicy, PSA, аудит, WireGuard) — обязательно; из агентов — один (Falco или Tetragon) с урезанными лимитами; Kyverno и оператор Kubescape — не ставить.

**Порядок (что делать первым).**
1. Сеть узлов: межсетевой экран и `wireguard-native` (строки 1–2) — первым, бэкенд flannel проще задать до развёртывания нагрузки [21].
2. k3s по hardening guide, secretbox, аудит, PSA restricted, ValidatingAdmissionPolicy «только digest» (3–5).
3. Qdrant: `api_key` на пирах, JWT `r` для поиска, NetworkPolicy на 6335, непривилегированный образ, отключить загрузку снапшотов по URL, CORS и телеметрию, аудит в stdout; p2p TLS — если успеваете (8–9).
4. Под поиска: без токена SA, restricted, ≥2 реплики, egress-allowlist без DNS (6–7, 16).
5. Ollama ≥0.17.1 за фильтр-прокси с одним `/api/embed` (12).
6. HAProxy: профиль Intermediate, 429/413, белый список путей, заголовки, TLS до Traefik, `retry-on` (10–11).
7. Falco с `http_output` в панель + «ответчик»: метка → карантин → удаление (15–16).
8. Прогон проверок «до/после», отчёты сохранить с датой и версиями (18).

**Сценарий для ролика.** Снаружи: (1) nmap — открыт только 443; (2) testssl.sh и `-tls1_1` — старые протоколы и слабые шифры отвергнуты; (3) флуд — 429, `/collections` и `/docs` — 404/403. «Заражённый под» (shell через `kubectl exec`; в кадре сказать, что это симуляция RCE): `curl` наружу, к API Kubernetes и к Ollama — таймаут или 403; `DELETE` коллекции — 403; порт 6335 недоступен; запись в ФС — read-only. Falco поднимает алерт → метка карантина → ReplicaSet сразу создаёт чистый под → заражённый удалён; генератор нагрузки работает без ошибок.

**Отложить.** KMS v2 — нет внешнего KMS [18]; mTLS сервис-сервис на Pod Certificates — нужен свой подписант [11]; admission-политики из манифестов (beta) [11]; проверку подписи в кластере (policy-controller) — после основного [53]; Kyverno и оператор Kubescape — память [54, 61]; Falco Talon — последний релиз v0.3.0, активность низкая [60]; PQ-TLS — нужна сборка HAProxy с AWS-LC [37]; блокировки Tetragon — как бонус вместо Falco [59].

**Честные ограничения (сказать в ролике).**
- NetworkPolicy не журналирует блокировки, а смена политики может не рвать уже открытое соединение (зависит от реализации) — поэтому после карантина под удаляем [15].
- Ключ шифрования секретов лежит на том же узле [18].
- Разрешённый DNS — возможный канал утечки (MITRE T1071.004) [47].
- Замена пода возвращает чистое состояние, но не исправляет уязвимость в приложении: тот же эксплойт сработает снова.
- Подпись ≠ доверие: вредоносный Trivy 0.69.4 собран штатным конвейером [48].

**Формулировки.** Корректно: «18.11.2026 на конфигурации X проверено N сценариев (список) — все заблокированы или обнаружены не позже чем за T с»; «конфигурация проверена по CIS Kubernetes Benchmark v2.0 (self-assessment k3s) и kube-bench 0.16.0: FAIL — 0, WARN — K, каждый объяснён»; «trivy 0.76.2, база от <дата>: уязвимостей Critical/High с доступным исправлением нет; неисправимые CVE Kubernetes [19] закрыты мерами …»; «это демонстрация защиты в глубину, не пентест и не аудит». Некорректно: «взломать невозможно», «100 % защищено», «сертифицировано CIS» или «полностью соответствует CIS».
